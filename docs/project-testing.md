# go-objects testing and maintenance

This guide owns contributor and release validation, including current performance reproduction commands. [package.json](../package.json) owns executable gates and pinned tools; the [full API reference](API.md) owns public contracts and the [README](../README.md) gives starting examples.

## Setup and gates

Use Node.js >=22.16.0 for development tooling. Run `npm ci`, `npm run docs`, and `npm run verify`. TypeScript parses canonical CommonJS for generation and compiles installed-consumer declarations. Pinned esbuild independently verifies tree-shaking; it is not a runtime dependency or the distribution generator.

`verify` runs the complete build, zero-warning ESLint, Prettier checks, read-only docs freshness/examples, source coverage, packed TypeScript consumers, build recovery, artefact freshness/loaders, tree-shaking, packed runtime consumers and bounded mutation checks. `verify:all` adds Chromium, Firefox and WebKit for both readable and minified UMD. `npm run verify` and `verify:all` each call `pack:package` once, then pass that one candidate tarball to installed-consumer checks. `npm run pack:package` builds fresh output and packs the generated `package/` directory into `artifacts/`. Root `prepack` and `prepublishOnly` reject accidental source-root packaging. Internal packing uses `--ignore-scripts` after the build.

Install Python browser tooling with `python -m pip install -r test/browser/requirements.txt`, then `python -m playwright install chromium firefox webkit`. `npm run test:browser` runs offline actual UMD, standalone ESM and static ESM via Blob import rewriting. Select `--browser firefox` or `--browser webkit` after installing the corresponding Playwright engine to run the same contracts there. The focused command defaults to Chromium; the full gate and CI run all three engines with both UMD bundles. Select `--bundle go-objects.min.js` for a focused minified check. Each run also loads the README script-tag example in a fresh page, intercepting only its exact-version bundle URL with the selected candidate bytes and checking its displayed result. This verifies script loading without relying on a published CDN version; it does not verify public CDN availability, CSP or the Safari application; Playwright WebKit is a separate engine test. For manual HTTP delivery, serve the project and open `test/browser/smoke.html`. Missing browser tooling fails explicitly.

Reports belong outside the checkout. Browser and mutation checks choose unique temporary report directories; type checks write a report only when passed an output filename. Individual command usage is documented below. Keep benchmark results temporary; reviewed release tarballs may remain in the ignored `artifacts/` directory.

## Regression coverage

- Runtime discovery includes only top-level `test/*.test.js`. `test/fixtures` contains shared cases, `test/types` compiler fixtures, and `test/browser` the real-browser harness. Build and artefact checks run separately, so runtime workers do not regenerate the shared checkout.
- Collection partitions cover symbols, descriptor combinations, sparse arrays, SameValueZero, literal/function matching, observed getter values and partial mutations.
- Path partitions cover grammar, numeric/symbol keys, malformed inputs, prototype-sensitive segments, read restrictions, updater effects and batch ordering.
- Immutable partitions cover frozen inputs, copied prototypes, sparse lengths, non-enumerable data, no-ops, missing containers and off-path alias identity.
- Deep/clone partitions cover ordering, depth cutoffs, cycles, first expansion, pruning, native brands, unsupported values and backing-buffer aliasing.
- Independent generated models cover collections, traversal, immutable spines, cyclic cloning and key collisions. Fixed seeds are 1, 0x12345678, 0xdeadbeef and 0xffffffff; failures name their seed. No timing assertions are used.
- Packed declaration tests cover NodeNext, Node16, Bundler, legacy Node/CommonJS, default optional semantics, UMD globals and ES2017 libraries without DOM/Node ambient types, with strict checking and `skipLibCheck: false`. An emitted fixture verifies runtime behaviour. Positive and negative matcher fixtures prevent functions bypassing callback checks as object literals. Receiver fixtures cover inferred/explicit `this`, bound and receiver-free callbacks, updater receiver rejection, wrapper replacement results and returned-function calls.
- Build fault injection covers generation, format validation, replacement, rollback and cleanup failures in disposable fixtures. Fresh builds are compared against every shipped generated file without altering the checkout.
- Mutation checks apply selected faults in disposable copies, verify a complete green baseline and valid syntax, and parse explicitly selected Node TAP. A mutation must run the same test inventory and count as its baseline. Missing/truncated summaries, skipped/todo/cancelled tests, timeouts, early worker exits and loading failures are infrastructure failures, not detected or surviving mutations. This is bounded assertion testing, not an exhaustive mutation score.

## Performance

`npm run benchmark` uses workloads in `benchmarks/`. For comparative measurements, supply an actual matching source baseline to `npm run benchmark:compare -- BASELINE_ROOT CANDIDATE_ROOT OUTPUT_JSON`. `BENCH_SAMPLES`, `BENCH_MS` and `BENCH_FILTER` control sampling; a filter matching no workloads fails instead of emitting an empty successful report. Both roots are loaded explicitly as directories (including their `main` entry), so adjacent `.js` or `.json` files cannot override the requested package. Reports include the selected absolute roots. `node scripts/test-performance-equivalence.js BASELINE_ROOT OUTPUT_JSON` compares seeded path parsing and reads with the explicitly supplied baseline, recording its version and the path/common source fingerprints.

The comparison alternates implementation order, consumes results, and keeps fixtures outside timed loops. The wrapper construction-only and reused-wrapper cases separate those costs from the combined wrapper/get workload. Allocation workloads include natural garbage collection. Report runtime, inputs and sample dispersion; do not turn local ratios into cross-engine promises. [The historical performance report](PERFORMANCE.md) retains the original 3.0.1 decision record and recorded commands; its old scratch artefacts have been removed and its results are not current measurements.

The coarse retained-heap guard runs in a fresh `--expose-gc` Node child: a short cached slice must not keep its large source string alive. It uses generous memory headroom rather than timing assertions, with a non-caching control. `scripts/test-performance-tools.js` checks experiment configuration and report integrity in `test:build`; absolute speed and GC scheduling are not unit-test contracts. Ordinary runtime memory size is engine-dependent. Run `node --test test/path-cache-retention.test.js` for the retained-string guard. The historical correction reduced the sliced-path diagnostic from about 64 MiB to about 22 KiB of retained heap, with a measured cost: the 4,096 rotating-path workload was about 80% slower in that original comparison. This is a correctness trade-off, not a current or universal performance claim.

## Generated package and documentation

`npm run build` generates the static ESM graph, root ESM entry, CommonJS per-function declarations, and UMD/standalone ESM bundles with their declarations. All generated formats and expanded export/type maps live in the complete ignored consumer `package/`; the private source-root manifest remains compact. Runtime syntax is downleveled to ES2017 and physical short CommonJS entries support runtimes without export maps. The build actually loads staged CommonJS, static ESM, bundled ESM, AMD and browser-global formats before replacing that one complete directory. It does not write root `dist/`, `esm/`, `index.mjs` or `src/*.d.ts`. A failed replacement restores earlier outputs; if filesystem errors prevent restoration, the error identifies the retained backup. The readable `dist/go-objects.js` and minified `dist/go-objects.min.js` include source maps and complete licence notices; `test:artifacts` checks both loaders and the README script-tag example.

Local experiments in `temp` or `.tmp` directories at any depth are preserved and excluded from Git, build inputs, package contents, linting, formatting, compiler fixtures and source coverage. Runtime test discovery selects maintained top-level test files only.

Package replacement preserves experiments inside the generated tree, including nested directories. Packing uses a filtered disposable copy so those retained files never enter the release archive.

The generated consumer manifest has no development dependencies or lifecycle scripts. Only runtime files, declarations, public documentation and required licence texts are copied. The setup and gates section above owns candidate packaging and browser setup.

Pass `npm run test:browser -- --output <file>`, `npm run test:mutations -- <file>`, or `npm run test:types -- <file>` to retain a report at a chosen path.

`npm run test:tree-shaking` bundles and executes a get-only consumer with esbuild. Without arguments it uses the generated `package/` (run `npm run build` first); `--package DIRECTORY` selects an existing installed candidate. The directory must identify the public go-objects package, and its name must resolve to that same directory, not to the private source root or an ancestor dependency. The check requires a contribution from the selected static ESM path implementation, excludes CommonJS/bundled fallbacks, and rejects retained clone, deep traversal, immutable mutation and wrapper code. Zero-byte inputs are not treated as retained code. It is part of the non-browser verification gate.

The offline browser runner derives import/export specifier ranges with the existing TypeScript parser before substituting Blob URLs. String, template and comment contents are not rewritten as imports. Test-owned graph and documentation transport fixtures guard this distinction without adding files to the consumer package. Their executions are reported separately from package graph modules and the per-format API scenarios. This remains a static, acyclic-module transport; it is not HTTP/CSP verification or a general browser module loader.

### Documentation command ownership

`npm run docs` regenerates the README and full API reference from `scripts/README.template.md` and `scripts/API.template.md`, package metadata and public exports. `npm run test:docs` checks freshness without writing, runs the shared README checker and validates examples. The installed-package gate applies the same checker to the archived README. Keep `scripts/lib/check-library-readme.cjs` identical to the canonical copy in the shared Instructions directory. This library retains its existing contributor-guide path as permitted by the shared documentation convention. Edit the template when changing prose.

Runtime tests and fixtures live in `test/`, compiler fixtures in `test/types/`, browser fixtures in `test/browser/`, benchmark workloads in `benchmarks/`, and command-line tools in `scripts/`. The TypeScript AST converter is retained because it already generates the static ESM graph without a runtime loader; Terser supplies the readable/minified UMD output and source maps. CI composes the same verification gates on Node 22 and 24, with a separate browser job for Chromium, Firefox and WebKit. The same generated tarball is installed and exercised on the minimum Node 8.0.0, representative legacy releases, and modern runtimes; Node 12.17.0 and 13.7.0 verify the native ESM floors. The Node 13.0 check protects CommonJS export-array fallbacks.

The full API reference supplies the README summary. Builds copy public tooltips from source comments and `types/api.d.ts` into the generated ESM graph and per-function declarations. The installed-consumer type gate also compiles the published TypeScript examples. Edit both templates and update public source/declaration tooltips together. Example checks execute displayed results and compile TypeScript blocks. Both documents and the migration guide ship; this contributor guide does not.

## Consumer runtime checks

Run `npm run test:runtime -- --node /path/to/node --tarball /path/to/go-objects.tgz` to validate an exact archive. Add `--esm` on Node 13.7.0 or later, or 12.17.0+ within 12.x. The modern orchestrator installs offline, runs CommonJS/UMD and optional native ESM contracts, compiles and executes TypeScript consumers, and reports the archive SHA-256. A missing supplied archive fails. Completion markers, checked after successful process exit, protect native and compiled consumers, displayed-result examples, installed import probes and staged build smoke checks. A zero exit alone does not prove the final assertions ran. Markers confirm the script reached its final check; they do not sandbox test code or prove that arbitrary unawaited work completed.

Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to an installed Chromium-compatible browser when using `verify:all`, or pass `--executable` to the browser command. With `--browser firefox` or `--browser webkit`, an optional `--executable` must identify that selected engine; the Chromium environment override is ignored.

## Lint and formatting ownership

Pinned ESLint 10, typescript-eslint and Prettier validate handwritten JavaScript, TypeScript declarations/fixtures, maintained nested JSON, Markdown and CI YAML. Run `npm run lint` and `npm run format:check`; `npm run lint:fix` and `npm run format` apply mechanical corrections. Node.js >=22.16.0 remains the contributor floor; consumer Node 8 is checked using the generated package. Generated `package/`, temporary reports and historical Markdown are excluded; the canonical documentation generator owns Markdown alignment. Inline exceptions preserve compile-only bindings, dynamic path widening, structural empty-type checks, callable exclusions, browser triple-slash references and deliberate malformed/sparse parser fixtures. Runtime rules stay enabled.

Keep temporary reports and release logs outside the library. Record current candidate identity and remaining release gates in the shared library tracker. Narrow fixture exceptions cover iterator cleanup that deliberately throws and bindings that assert callback receiver types.

The `test:build` command also runs process-infrastructure, consumer-completion and mutation-accounting regressions. Discovery and process fixtures use disposable directories. Verifier routing tests simulate the individual expensive gate commands: they verify candidate forwarding, failure propagation and cleanup, not the underlying build, install or browser gates.

Build-conversion regressions change source only in disposable fixtures, then compare canonical CommonJS, generated CommonJS, static ESM, bundled ESM, CommonJS-loaded UMD and browser-global UMD values in a fresh process. They protect export-like template data, default/namespace dependency bindings and actual ES2017 lowering. Negative facade tests require an explicit failure with the previous package untouched. Recovery controls also cover first-build generation failures, failure to save old output and post-install backup-cleanup failures; a retained validated package after failed cleanup does not count as a successful build. These Node/VM format checks do not substitute for real-browser or minimum-runtime gates.

A build regression snapshots pre-existing legacy root outputs and proves they remain untouched. Stale files are removed only from the newly generated package tree. Tests use that tree for module-format checks and exact installed tarballs for consumer declarations, tree-shaking, runtime and browser checks. The packed inventory is compared with an explicit list derived from public functions and canonical implementation modules.

The consumer-check regressions in `scripts/test-consumer-contracts.js` are included in `test:build`. Their esbuild fixtures simulate candidate routing and documented metafile results to verify rejection/acceptance logic; passing those fixtures does not establish that the pinned real esbuild integration ran. The source-fidelity cases use actual Node ESM evaluation, and `test:browser` exercises the shared parser/Blob transport in Chromium. Missing compiler, bundler or browser tooling still fails the relevant gate; do not substitute fixture results for a blocked integration.

### Source-faithful documentation examples

Displayed-result checks recognise actual single-line `// =>` comments, not annotation-like text inside strings, templates, regular expressions or block comments. Annotated returns preserve their value and control flow, evaluating the returned expression once. An annotation is expected to execute once; the runner fails when displayed checks are missed or repeated. Incorrect results, incorrect error types and incomplete child processes remain failures.

The additional ESM pass converts only top-level, single-binding `const name = require('go-objects[/subpath]')` declarations. It is not a general CommonJS-to-ESM converter. Module-kind detection uses the parsed program, so import-looking data does not switch its execution mode. Published TypeScript examples are compiled without rewriting their source, through a disposable local package-resolution link to the selected generated or installed candidate. Root, documented subpath and type imports use that candidate's export map. Cleanup removes the temporary link, not its target. The source-fidelity and annotated-return regressions live in `scripts/test-docs.js` and run under `test:docs`.

## TypeScript compatibility

The deferred inference helper preserves known paths, mutation domains, callback inference and immutable results. TypeScript 5.2 loses existing contracts. Automatic predicate inference is additionally checked on TypeScript 5.5 and newer; older consumers can write explicit type predicates.

Run `npm run test:types -- --compiler /path/to/typescript/lib/tsc.js --package /path/to/installed/go-objects` to check an external compiler against a built or installed package. The default uses the pinned development compiler. The same inference and rejection fixtures are reused for the supported minimum (5.3.3) and the pinned compiler; CI checks the exact candidate tarball with both. Legacy checks adapt fixture extensions and import syntax only where needed. Node16/NodeNext, Bundler and exact optional properties remain enabled in the configurations that support them.
